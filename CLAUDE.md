# CLAUDE.md — SigPort

SigPort audits how portable a published gene-expression signature is across cohorts and
measurement platforms, and attributes performance loss to three separable causes:

- **(a) recoverable naming drift** — the gene is on the platform under an older/alternative symbol
- **(b) genuine absence** — the platform has no probe/feature for the gene at all
- **(c) residual differences** — biology, batch, normalisation, platform scale; whatever is left
  once (a) and (b) are accounted for

Scope for this version: human breast cancer signatures, bulk expression (Affymetrix arrays and
RNA-seq), Python. Research-grade, not a product. The owner is a computational biology student
who uses this repo to learn; **the owner makes every decision and every commit.**

## 3. Coding conventions

- Python ≥ 3.11, `src/` layout, installed with `pip install -e .`. Type hints on all public
  functions. Docstrings: one-line summary, then Args/Returns, then the one-sentence method note
  where a statistic is involved.
- `pandas` for tables, `numpy` for arrays, `scipy.stats` + `scikit-learn` for stats/metrics,
  `typer` for CLI, `matplotlib` only (no seaborn) for the figure, `pytest` for tests.
- Pure functions in library modules; I/O and printing only in `io.py`, `cli.py`, `scripts/`.
- Every reader in `io.py` returns `(DataFrame, meta)` where `meta` has `path`, `sha256`,
  `n_rows`, `n_cols`, `read_at`. Readers assert `n_rows > 0` and compare to an expected count
  when one is supplied.
- Symbols are compared **case-sensitively after `.strip()`**; never upper-case them silently
  (HGNC symbols are case-sensitive: `C19orf71`).
- Multi-valued cells in GEO annotation (`"KRT17P1 /// KRT17"`) are split on `" /// "` and every
  symbol kept. Entrez multi-values likewise.
- Output tables are TSV, one row per (signature, platform, gene), written to `results/`.
- Logging via `logging`, module-level logger; CLI sets level from `-v`.
- Tests must run offline using `tests/fixtures/` only. No network in tests.
- Keep functions under ~40 lines; split rather than nest.
- Formatting: `ruff format` + `ruff check` (config in pyproject). Don't argue with the formatter.

## 4. Key design decisions (do not re-open without the owner)

**HGNC snapshot.** Use one frozen monthly archive, e.g.
`https://storage.googleapis.com/public-download-files/hgnc/archive/archive/monthly/tsv/hgnc_complete_set_YYYY-MM-01.txt`
plus the matching `withdrawn.txt`. Record filename, date, sha256 in `data/snapshots/SNAPSHOT.md`.
All resolution is against this file; `--snapshot` CLI flag can point to another. The snapshot date
is printed in every report header.

**Resolution categories** (`resolve.py`, column `category`, exactly one per input symbol):

| category            | meaning                                                                 |
|---------------------|-------------------------------------------------------------------------|
| `exact`             | input == `symbol` (approved) in snapshot                                |
| `previous`          | input in `prev_symbol` of exactly one gene                              |
| `alias`             | input in `alias_symbol` of exactly one gene (and not an approved symbol)|
| `ambiguous`         | input matches ≥2 genes via prev/alias, or matches one gene's approved symbol AND another's alias/prev — report all candidate HGNC IDs, do not pick |
| `withdrawn`         | input in `withdrawn.txt` with no merged-into target                     |
| `unresolved`        | not found anywhere in the snapshot                                      |

Resolution returns `hgnc_id`, `approved_symbol`, `entrez_id`, `ensembl_gene_id`, `category`,
`candidates` (pipe-joined when ambiguous). **Both sides are resolved**: signature symbols AND
platform symbols are mapped to HGNC IDs, then intersected on HGNC ID. A platform annotation from
2002 uses old symbols too; comparing raw strings on either side is the bug we are fixing.
Where a platform file carries Entrez IDs, intersection on Entrez is computed as a second channel
and disagreements between the symbol-channel and Entrez-channel are reported, not hidden.

**Audit categories per signature gene × platform** (`audit.py`, column `status`):

| status                 | derived from                                                      |
|------------------------|-------------------------------------------------------------------|
| `present_exact`        | raw symbol string present on platform                             |
| `present_after_resolve`| absent as raw string; present after HGNC-ID intersection (= recoverable drift) |
| `absent`               | HGNC ID resolved, but no platform feature maps to it (= genuine absence) |
| `ambiguous`            | resolution ambiguous on either side; counted separately, never as present |
| `unresolved`           | signature symbol not in HGNC snapshot at all                      |

**Impact analysis** (`impact.py`). Three evaluations per signature × target platform:
1. *naive*: use only `present_exact` genes;
2. *resolved*: use `present_exact + present_after_resolve`;
3. *oracle*: all signature genes (only possible on a platform that has them all, e.g. TCGA).
Loss(naive→resolved) is attributed to (a); loss(resolved→oracle) to (b); the remainder vs the
training cohort to (c). Metrics: for PAM50, subtype-call agreement and Cohen's κ against oracle
calls; for prognostic/ER signatures, ROC AUC against the available label.
Nulls and CIs: *simulated dropout* — drop the same number k of genes chosen at random, repeat
N=1000, giving a null distribution of the metric for "any k genes" so we can ask whether the
genes actually missing are worse than chance; *bootstrap* — resample samples with replacement,
B=1000, percentile 95% CI for every reported metric. Seeds fixed.

**Figure.** One headline figure: x = platform, y = metric (κ or AUC), three points per platform
(naive / resolved / oracle) with bootstrap CI bars and the dropout-null band in grey.

## 7. How to work a task

1. Read the task line and the relevant module(s). Restate the task in two lines.
2. Write the test or fixture first when the task has a checkable number.
3. Implement. Keep the diff small. Don't refactor unrelated code.
4. Run `pytest -q` and the task's "Check" command yourself; paste the exact output.
5. Tell the owner: files changed, the check command to run, the number(s) they should see.
6. Stop. Then write/update the session draft (§8).

## 8. Session draft format — `notes/session_drafts/YYYY-MM-DD.md`

Plain facts, third person or imperative, no narrative, no adjectives like "surprising".
Numbers exact, with units and the file they came from. Sections, always in this order:

```
# Session draft YYYY-MM-DD

## Task(s) worked
- <task id and one line>

## Commands run
- `<command>` → <one-line result / key number>

## Files changed
- path — what changed (1 line)

## Numbers / outputs
- <metric or count>: <value> (source file / command)

## Bugs found
- <symptom> — <cause> — <how it was caught (test / assertion / manual check)> — <fix>

## Open questions
- <question the owner needs to decide or verify>

## Next task
- <id>
```

If nothing happened under a heading, write `- none`. Never write in first person as the owner.
